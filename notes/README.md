Goal: bring RS3 back to life, ultimately as a browser build that runs on iOS Safari.

## Data formats
- DataBin/*.mfd container: u32 count; count × (u32 id, u32 offset, u32 size); payloads follow. Verified on all 60 archives (tools/mfd_ls.py). Ids are small ints (probably hashed/indexed names); FMap.bin maps archive names.
- Track archive (TracksN.mfd, 17–18 entries each, 16 tracks): chunk magics seen: "\x04MMB", "\x04M3D" (mesh, 2.7–2.9 MB, two per track), "\x04H3D" (×2), "\x04ZON", "\x04BSP", "PoE", plus small tables.
- TxTrN.mfd: ~400–540 textures/track, each starts 00 00 02 00 ...; TxCars.mfd 1141 textures; TxTrkCom.mfd 713 shared.
- MechaCar.mfd 304 entries (car models/physics), Anim.mfd 594, Sound/MenuSnd (sample banks), Scenarii.mfd 41, GameDB.mfd 14, Localize.mfd 15, Camera.mfd 2.

## Web-port strategy (decided 2026-10-22)
Engine re-implementation in the browser (TypeScript + WebGL/WebGPU), driving the ORIGINAL assets, with physics/AI/rules ported function-by-function from Ghidra decomp of RS3.exe guided by PS2 symbol names. Not emulation (PS2-in-WASM is unplayable on iPhone), not static recompilation (no mature x86/EE recompiler for this).
Phases: 1) asset extraction + track viewer in browser · 2) car model + F1MC physics port, drive a lap · 3) AI (AIF1), rules (F1SP), timing (STRC), replays · 4) menus, audio, localization, polish.

## Format findings (22 Oct, evening)
- Textures = plain uncompressed TGA (type 2, 24/32bpp, BGR(A), bottom-left origin, 26-byte TRUEVISION-XFILE footer). 9,309 extracted by tools/tex_extract.py. Track textures come in 4-level mip chains as separate entries.
- Track chunks are Ubisoft DCHK files (tools/dchk.py): 8-byte file header [align, 3-char tag, .., flag]; chunk = u32 id, u32 size; id bit24 = leaf, bit25 = reference, id&0x7fffff = type; types 0x7ffffe/0x7fffff = ref tables. Source: DCHK_InputBinaryFile decomp (decomp/ps2_loaders.c, via Ghidra 12.1.4 + ghidra-emotionengine-reloaded r5900 language).
- MMB (collision, F1CL_M3DMechaReader::pvReadRoadAndWall): root 0x100000 DIR → leaf type0: u32 nVerts, nVerts×vec3f, u32 nTris, nTris×{u32 a,b,c, u16 material, u16 flags}; type1: nTris×3×{i16 neighbourTri, i16} adjacency; type2: quadtree (node: 4×u32 isLeaf + child; element: 16-byte bbox; F1CL_QTLeaf: 3 u16 lists); type3: walls (u32 n, n×vec2f; u32 nW, nW×{i32 i1,i32 i2,u32 mat}, nW×{f,f}); type4: unknown (1611 × ?). Plot of verts = Albert Park outline (out/mmb_xy.png). Coordinates: x,y ground plane, z up (z range −4.8..−2.2 m).
- M3D (render mesh, PC-specific DCHK layout; PS2 uses DIDA_MdaReader instead): 0x7fffff/0x7ffffe ref tables first; then repeated [0xf DIR pool + N × 0x19 DIR group]. Pool leaves: 0x10 positions (u32 n, n×vec3f), 0x11 UVs (n×vec2f), 0x12 normals (n×vec3f), 0x13 colours (n×RGBA8), 0x78 vertex records (n×8 bytes: u16 normalIdx, u8 colourIdx, u8 ?, u16 uvIdx, u16 posIdx), 0x16 REF ×k = texture references (ref table 1, index k), 0x17 REF. Group leaves: 0x7f index list (u32 n, n×u16 into pool records, triangle STRIP with degenerate joins), 0x36 u32, 0x37 u32, 0x80 vec3 centre, 0x81 bbox min/max.
- M3D corrections (verified in viewer): 0x7f is a plain TRIANGLE LIST (quads = (a,b,c),(c,d,a)), indices relative to group base 0x36. Per-pool 0x39 blocks come AFTER all pools (one per pool, in order); their 0x3a REF (3,k) entries map group k → material index. 0x22 = material: 0x23 id (4000+i), 0x24/0x25/0x26 ambient/diffuse/specular RGBA8, 0x27 = texture layer DIR (0x2d flags, 0x91 texture .mfd entry id, 0x92 mip entry ids); 0x3b/0x3c/0x30..0x34 extra layer params on ~26 materials (env/lightmap?). Texture ids resolve to TxTrN.mfd or TxTrkCom.mfd entries. 0x16 REF (1,k) in pool = pool→group k, 0x17 REF (2,k) = pool→0x1e bounds. Ref-table offsets are relative to the start of the 0x7ffffe table. 0x37 meaning still unknown.
- Viewer: ~/rs3-port/web (Vite+Three, `npx vite --port 4790`), /data symlink → DataBin. ?track=N, &mmb shows collision wireframe. Track 0 = Albert Park (named "New Zealand" in-game).

## Session 2 (22 Oct, late): data layer complete, physics port begins
- Direction from Max: quality over speed → port the real F1MC physics, no arcade stand-in; material system must match original.
- BSP "variables" format (tools/bsp.py, decoded 193/193 chunks → out/setups/*.json): root DIR; leaf0 u32 count; per var DIR type1 { leaf0: u16 len + name, value leaf }. Value types: 1/size8 = (u32 kind, f32); 1/size>8 = (u32 n, n×f32) vector; 2 = (u32 kind, i32) int/bool/enum; 5 = sampled curve (u32 kind, u32 n, f32 xmin, f32 xmax, n×f32 y). MechaCar.mfd: 0x3786-style chassis files (196 vars: geometrie, collision spheres, damage, suspension, aero wings slow/medium/fast with Cx/Cz curves, brakes, propulsion engine/clutch/gearbox/differential), 0x17 = tyre file (262 vars, curves), 0x2ed8 = wear. 22 cars.
- MechaCar.mfd M3D: same layout as tracks; textures in TxCars.mfd. 44 M3D = 22 cars × (full ~277 KB + materials-only ~18 KB variant). Car model units metres, z up.
- Tracks: entry 0x216d = grid slots: 16-byte header (22, 11, 22, 1) then 22 × {vec3 pos, vec3 dir}; 0x21a2 = 42 × 56-byte records (pit/marshal positions?). MMB type 3 walls: 1611 2D points, 1596 walls {i32 p1, i32 p2, u32 material}, then per wall {f32 zbottom, f32 ztop}; type 4: 1387 × 28-byte records (3D wall quads?). Road triangles: material ids 1..7 (surface types), flags all 0.
- Physics architecture (PS2 decomp, decomp/ps2_physics.c 778 fns + ps2_math_race_ai.c + ps2_mec_cam_view.c): F1MC_F1Car : MEC_PhysicalSolid (rigid body, quaternion state at +0xc0, flags +0xe0, torsor force +0x270 / torque +0x280, vFPM integrator, vSumTorsors). vMove(dt): mode 0 full sim / 3 simplified. Steps: vComputeAnnexData → vApplyCommands → vDistributeEngineTorque → (wheel Z forces, XY forces, aero) → vSumTorsors → vAddReactionForceInSlope → vFPM → wall collisions (F1CL_CollisionModel::bComputeCollisionsWithWall) → speed cap. PART_Wheel = tyre model (slip angle, XY force, imposed forces), PART_ShockAbsorber, PART_AutomaticGearBox, F1MC_Engine, F1MC_Wheel (temperature/wear/grip), F1CL_CollidingSphere (contact spheres vs road triangles), COL_CollisionSolver (impulses). Focused reading files: decomp/read_vMove.c, read_car_forces.c, read_wheel.c, read_engine_gearbox.c, read_car_init.c.

- M3D vertex records (0x78) CORRECTION: u32 count, then descriptor [nComponents][component ids] padded to 4 bytes, then count × (nComponents × u16). 3 comps (ids 0,1,2) = (pos, nrm, uv) — cars; 4 comps (ids 0,1,3,2) = (nrm, col, uv, pos) — tracks. ## 23 Oct 2026 — M3D record/triangle layout fixed, car parts identified, mirror removed
- 0x7f group chunk = u32 nTris, then nTris×3 u16 record indices (pad to 4). Earlier parser read only nTris indices → one third of every group drawn → the "ground holes".
- 0x78 vertex records: u32 count; descriptor = u8 nc + nc×u8 component id, padded to EVEN length (4 bytes for nc=3, 6 for nc=4/5); then count×(nc×u16). ids: 0=pos 1=nrm 2=uv (second 2 = uv2) 3=colour. Indices are 0-based for every pool (the old "1-based for wide pools" rule was compensating for the 2-byte descriptor error). Verified on Albert Park, Tracks5 and car meshes: every field max < array length.
